Getting Started

One-Minute Quick Start

Nitron packages the static output of whatever you already use to build your site. Point entry at your built index.html.

For projects with standard HTML, CSS, and JavaScript files:

# 1. Initialize project config
npx nitron init --preset vanilla

# 2. Build your Android APK (test on any device)
npx nitron build

# Output: dist/app.apk (~214 KB) ready in 2 seconds!

Works with Vite's standard build. Absolute paths such as /assets/script.js resolve seamlessly on Nitron's safe HTTPS origin without needing base: './'.

# 1. Initialize Vite preset in your Vite project directory
npx nitron init --preset vite

# 2. Build static assets
npm run build

# 3. Package into native APK
npx nitron build

Next.js is supported through static export. Add output: "export" to your next.config.js.

# 1. Initialize Next.js preset (points entry to "out/index.html")
npx nitron init --preset nextjs

# 2. Build Next.js static export
npm run build

# 3. Build native APK
npx nitron build
⚠️ Dynamic Routes Note
Next.js static export rejects dynamic routes like /products/[id]/page.tsx unless you supply generateStaticParams. For apps, use query parameters instead (/products/detail?id=...) and read it with useSearchParams() inside a <Suspense> boundary.

Build iOS apps using the same config through the initron engine (WKWebView shell):

# Build an unsigned .app for testing in the iOS Simulator (No Apple Developer account needed)
npx nitron build --target ios-simulator

# Build a signed .ipa for real device / TestFlight / App Store (Linux or WSL2, no Mac needed!)
npx nitron build --target ios
Configuration

Declarative Configuration

Everything lives in nitron.config.json. Pure JSON, no ES Module / CommonJS confusion, and completely CI/CD friendly.

{
  "name": "My App",
  "packageId": "com.myname.myapp",
  "version": "1.0.0",
  "entry": "out/index.html",
  "orientation": "portrait",
  "statusBar": true,
  "permissions": ["INTERNET", "ACCESS_NETWORK_STATE", "CAMERA"],
  "icon": "./public/icon.png",
  "exclude": ["*.exe", "my-backend-folder", "secret.config"],
  "network": { "cleartext": false },
  "webview": {
    "backButton": "history",
    "clearCacheOnStart": false,
    "externalLinks": "browser",
    "allowedHosts": ["pay.example.com"]
  },
  "splashScreen": { "backgroundColor": "#0F121D" },
  "android": { "targetSdk": 36, "minSdk": 21 }
}
namestring
The application display name shown on device home screen and launcher.
packageIdstring
Unique reverse-DNS package identifier (e.g. com.company.app). Min 3 segments.
webview.externalLinks'browser' | 'inapp'
New in v3.1.5: Defaults to "browser" to keep third-party links outside the bridge WebView.
webview.allowedHostsstring[]
Hostnames allowed to open inside WebView when externalLinks is 'browser' (e.g. payment/auth gates).
excludestring[]
Glob patterns or exact folder names kept out of the final APK/IPA bundle to reduce bundle size.
android.targetSdknumber
Target Android API level. Defaults to 36 (compliant with newest Google Play mandates).
Runtime Bridge

Built-in Native APIs

Nitron exposes a secure zero-dependency bridge to your client JavaScript as window.Nitron without requiring third-party plugins.

🔔

System Push Notifications

Trigger native Android system notifications directly from your web UI. Automatically requests notification permissions on Android 13+.

// Call from your JavaScript code:
window.Nitron.showNotification(
  'Order Confirmed',
  'Your package is on its way!'
);
📍

Runtime Permissions

Request native device permissions on-demand with built-in checkSelfPermission checks to prevent annoying redundant dialogs.

// Native permission requests:
window.Nitron.requestLocationPermission();
window.Nitron.requestCameraPermission();
window.Nitron.requestStoragePermission();
Security Architecture

Defense in Depth Security Model

Nitron is engineered specifically to prevent malicious web exploits and bridge injection vulnerabilities.

🛡️

Safe Local Origin

Local files are served over https://appassets.androidplatform.net via Android's modern shouldInterceptRequest. No insecure file:// URLs or dangerous universal access permissions.

🔒

External Link Isolation

External links load in the system browser by default. This ensures untrusted third-party websites never have access to the native window.Nitron bridge.

🎯

Exact Host Origin Check

In v3.1.5, origin validation performs an exact hostname comparison. Look-alike phishing domains (such as appassets.androidplatform.net.evil.com) are strictly rejected.

Publishing

Publishing to Google Play Store

Google Play requires an Android App Bundle (.aab) and a persistent release keystore.

🔑

Step 1: Generate Release Keystore

Run once to generate your cryptographic release key. Keep this file safe; you cannot update your app in Google Play without it.

npx nitron keystore
# Generates: nitron-release.keystore
📦

Step 2: Build Signed AAB

Build an optimized, signed Android App Bundle ready to upload directly to the Google Play Console.

npx nitron build --target aab --release
# Generates: dist/app.aab (Play Store compliant)
Cross-Platform Engine

iOS Support without macOS (initron)

Nitron builds genuine iOS apps using the same nitron.config.json, with a WKWebView shell compiled directly on Linux or WSL2.

How iOS Cross-Compilation Works

Instead of requiring macOS and Xcode, Nitron employs an isolated open-source cross-compilation toolchain based on cctools-port, apple-libtapi, and zsign.

  • Pure Mach-O arm64 Binary: Real native executable generated without Xcode.
  • Standard Payload Structure: Creates Payload/App.app/... directory format accepted by App Store & TestFlight.
  • zsign Code Signing: Signs the application with your Apple Developer Certificate (.p12 + .mobileprovision).

iOS CLI Commands

# 1. Unsigned .app for iOS Simulator:
npx nitron build --target ios-simulator

# 2. Signed .ipa for real iPhone/iPad:
NITRON_IOS_P12_PATH=./cert.p12 \
NITRON_IOS_P12_PASSWORD=secret \
NITRON_IOS_PROVISION_PATH=./profile.mobileprovision \
npx nitron build --target ios
Architecture

Nitron Dual-Engine Architecture

A decoupled, high-performance architecture separating platform-agnostic core logic from specialized build engines.

Shared Agnostic Core

cli.ts • config.ts • validator.ts • types.ts • pwa.ts • dev.ts

🤖 Nitronoid (Android Engine)

Produces signed APK & AAB packages in under 2 seconds without Gradle.

  1. Unpack: Extracts pre-compiled base.apk template.
  2. Inject Assets: Injects web files into assets/www/.
  3. Compile Resources: Runs lightweight aapt2 for icons and manifest.
  4. Pack & Sign: Packages via jszip and signs with uber-apk-signer.

🍎 Initron (iOS Engine)

Produces Mach-O arm64 IPA & Simulator .app bundles without Xcode.

  1. Unpack Shell: Extracts pre-compiled WKWebView native shell.
  2. Inject Assets: Copies web files into NitronShell.app/www/.
  3. Generate Plist: Patches XML Info.plist with permissions and metadata.
  4. Codesign: Signs with zsign and packages into dist/app.ipa.
Release History

Nitron Changelog

Track releases, security fixes, and feature additions.

v3.1.5 (Latest)

Security Hardening & Toolchain Improvements

  • External Links Default to System Browser: webview.externalLinks defaults to "browser", preventing third-party websites from loading inside the bridge WebView.
  • Exact Hostname Origin Checks: Strict origin validation for bridge calls and geolocation; rejects spoofed hostnames like appassets.androidplatform.net.evil.com.
  • XML Sanitization: Values written to AndroidManifest.xml (app name, splash color) are escaped to prevent XML injection.
  • Auto-downloading Toolchain: scripts/prepare-template.js automatically locates or downloads android.jar and R8 dexer from Google Maven.
  • License Clarification: Formally designated as GPL-2.0-only with the Nitron Output Exception.
v3.1.0 – v3.1.4

Asset Exclusion & SDK 36 Support

  • Asset Exclusion: Added exclude array in nitron.config.json supporting glob patterns (e.g. *.exe).
  • Android 16 Support: Default targetSdk raised to 36 with Play Console warnings.
  • AAB Fixes: R8 mapping and network security fixes for Google Play bundles.
v3.0.0

iOS Engine (initron) & Architecture Restructuring

  • New iOS Engine: Cross-compile native iOS apps from Linux using WKWebView shell.
  • Dual-Engine Architecture: Clear separation between nitronoid (Android) and initron (iOS).
v2.1.0

Native JS Interface & HTTPS Local Origin

  • window.Nitron: Added native JavaScript APIs for Location, Camera, Storage, and Push Notifications.
  • Secure Origin: Migration from file:// to https://appassets.androidplatform.net.
  • AAB Export: Initial support for Google Play App Bundles.
